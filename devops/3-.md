# 03

Following security audits, the xFusionCorp Industries security team has rolled out new protocols, including the restriction of direct root SSH login.



Your task is to disable direct SSH root login on all app servers (stapp01, stapp02 and stapp03) within the Stratos Datacenter. Make sure the change is applied to the running SSH service on each server.

To disable direct root SSH login across all application servers (**stapp01**, **stapp02**, and **stapp03**), you need to update the SSH daemon configuration file on each server and restart the running SSH service.

### Step-by-Step Procedure

Log into each server sequentially (or use your configuration management tool) and perform the following commands:

1. **Access the App Server:** Via SSH.
Connect to the target application server using your designated administrative user account:

```bash
ssh tony@stapp01.stratos.xfusioncorp.com

```

*(Substitute `tony`, `steve`, or `banner` along with the correct hostname for stapp02 and stapp03 as applicable).*

*Verification:* Ensure you are successfully logged into the command line interface of the target server.


2. **Switch to Elevated Privileges:** Root Access.
Switch to the root user or run subsequent commands with `sudo` privileges to modify system configuration files:

```bash
sudo -i

```

*Verification:* Your terminal prompt should change to indicate root access (e.g., ending with `#`).


3. **Edit the SSH Configuration File:** /etc/ssh/sshd_config.
Open the SSH daemon configuration file using a text editor like `vi`:

```bash
vi /etc/ssh/sshd_config

```

Locate the line containing `PermitRootLogin` (it is often commented out as `#PermitRootLogin yes` or set to `yes`). Change it to:

```text
PermitRootLogin no

```

*(Make sure to uncomment the line by removing the `#` symbol if present).* Save and exit the editor.

*Verification:* Run `grep -i permitrootlogin /etc/ssh/sshd_config` to confirm the line is set properly and uncommented.


4. **Restart the SSH Service:** Apply Changes.
Restart the SSH daemon to ensure the running service picks up the new security rule immediately:

```bash
systemctl restart sshd

```

*(Note: On some distributions, the service name may be `ssh` instead of `sshd`).*

*Verification:* Check the active status of the service to confirm a clean restart:

```bash
systemctl status sshd

```


Repeat these steps for **stapp02** and **stapp03** to complete the rollout across all Stratos Datacenter application servers.
